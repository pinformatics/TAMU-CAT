# Archive Policy

## Purpose

This policy explains how to treat old students, retired advisor competency fields, and historical competency records.

## Student Lifecycle

Use lifecycle status instead of deleting students whenever possible.

Recommended states:

- current students remain active
- graduated students are archived after final reporting is complete
- withdrawn or inactive students are archived with a reason

Archived students should remain available to admins in historical filters.

## When To Archive Graduated Students

Archive after:

- final semester course competency imports are committed
- portfolio export needs are complete
- advising records have been reviewed
- required program reports have been exported
- any pending student matches have been reconciled or documented

## What Archiving Should Preserve

Archiving should preserve:

- survey responses
- advisor feedback history
- confidential advisor notes
- course competency evidence
- derived competency ratings
- import audit logs
- export audit logs

Do not delete historical competency records solely because a student graduated.

## Retired Advisor Competency Fields

Advisor numeric competency ratings are being retired in favor of course-derived competency inputs.

Keep historical advisor ratings visible where needed, but label them as historical or legacy. They should not override course-derived competency ratings.

## Export Retention

Student-level exports can contain FERPA-sensitive data.

Recommended handling:

- create exports only for legitimate educational interest
- store exports in approved TAMU locations
- delete local downloads when no longer needed
- do not commit generated student-level exports to the repository

## Import Files and Correction Files

Keep original import files and correction files only as long as needed for operational review and compliance.

Do not commit real student import files to the repository.

Sample files committed to the repository must use fake student data.
